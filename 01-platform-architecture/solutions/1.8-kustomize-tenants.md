# Solution 1.8 – Tenants with Kustomize

```bash
mkdir -p /tmp/tenants/base /tmp/tenants/overlays/{team-a,team-b}
cd /tmp/tenants
```

`base/kustomization.yaml`
```yaml
apiVersion: kustomize.config.k8s.io/v1beta1
kind: Kustomization
resources:          # the namespace comes from the overlay
  - quota.yaml
  - limitrange.yaml
  - netpol.yaml
  - rolebinding.yaml
```

`base/quota.yaml`
```yaml
apiVersion: v1
kind: ResourceQuota
metadata:
  name: tenant-quota
spec:
  hard:
    requests.cpu: "1"
    requests.memory: 2Gi
    pods: "20"
```

`base/limitrange.yaml`
```yaml
apiVersion: v1
kind: LimitRange
metadata:
  name: tenant-defaults
spec:
  limits:
    - type: Container
      defaultRequest: {cpu: 100m, memory: 128Mi}
      default: {cpu: 500m, memory: 512Mi}
```

`base/netpol.yaml`
```yaml
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: default-deny
spec:
  podSelector: {}
  policyTypes: [Ingress]
```

`base/rolebinding.yaml`
```yaml
apiVersion: rbac.authorization.k8s.io/v1
kind: RoleBinding
metadata:
  name: devs-edit
roleRef:
  apiGroup: rbac.authorization.k8s.io
  kind: ClusterRole
  name: edit
subjects:
  - apiGroup: rbac.authorization.k8s.io
    kind: Group
    name: PLACEHOLDER
```

`overlays/team-a/kustomization.yaml`
```yaml
apiVersion: kustomize.config.k8s.io/v1beta1
kind: Kustomization
namespace: team-a           # sets metadata.namespace on all objects
resources:
  - ../../base
  - namespace.yaml
labels:
  - pairs:
      team: team-a
patches:
  - target: {kind: ResourceQuota}
    patch: |-
      - op: replace
        path: /spec/hard/requests.cpu
        value: "2"
  - target: {kind: RoleBinding}
    patch: |-
      - op: replace
        path: /subjects/0/name
        value: team-a-devs
```

`overlays/team-a/namespace.yaml`
```yaml
apiVersion: v1
kind: Namespace
metadata:
  name: team-a
```

`overlays/team-b/` – identical, with `team-b`, `"6"` and `team-b-devs`.

```bash
kubectl kustomize overlays/team-a      # preview
kubectl apply -k overlays/team-a
kubectl apply -k overlays/team-b
kubectl auth can-i create deploy -n team-a --as=x --as-group=team-a-devs   # yes
kubectl auth can-i create deploy -n team-b --as=x --as-group=team-a-devs   # no
```

> Tip: This is the same pattern you will later automate with Argo CD ApplicationSets (2.2) or
> Kyverno `generate` (3.6).
