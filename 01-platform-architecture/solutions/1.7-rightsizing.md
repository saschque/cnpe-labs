# Solution 1.7 – Right-sizing

```bash
kubectl -n rightsizing top pod -l app=oversized
# e.g.: oversized-xxx   0m   3Mi   → an idle nginx needs almost nothing

# Requests to the minimum values (≈1.2 × usage, but at least 10m/16Mi), memory limit = 2 × request
kubectl -n rightsizing set resources deploy oversized \
  --requests=cpu=10m,memory=16Mi --limits=memory=32Mi

# Remove the CPU limit (set resources cannot delete limits → JSON patch)
kubectl -n rightsizing patch deploy oversized --type=json \
  -p='[{"op":"remove","path":"/spec/template/spec/containers/0/resources/limits/cpu"}]'

kubectl -n rightsizing scale deploy oversized --replicas=2
```

**Why no CPU limit?** CPU is compressible – limits cause CFS throttling and latency spikes even
when the node has spare capacity. Memory is not compressible, so a memory limit stays (otherwise
there is an OOM risk for neighbors).

**In practice:** derive the values from Prometheus over a longer period, e.g.
```promql
quantile_over_time(0.95, rate(container_cpu_usage_seconds_total{namespace="rightsizing",container="web"}[5m])[7d:5m])
```
or use the Vertical Pod Autoscaler in `Off` mode as a recommender.
