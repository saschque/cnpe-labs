# Solution 1.12 – Capacity analysis

```bash
# Convert CPU values like "250m", "1", "0.5" to millicores
JQ_CPU='def mcpu: if . == null then 0
                 elif test("m$") then (.[:-1] | tonumber)
                 else (tonumber * 1000) end;'

# Sum of CPU requests per node (running pods only; init containers ignored for simplicity)
kubectl get pods -A --field-selector=status.phase=Running -o json | jq -r "$JQ_CPU"'
  [.items[] | {node: .spec.nodeName,
               cpu: ([.spec.containers[].resources.requests.cpu | mcpu] | add)}]
  | group_by(.node)[] | "\(.[0].node) \(map(.cpu) | add)"' > /tmp/node-requests.txt
cat /tmp/node-requests.txt

# Namespace with the highest CPU requests
kubectl get pods -A --field-selector=status.phase=Running -o json | jq -r "$JQ_CPU"'
  [.items[] | {ns: .metadata.namespace,
               cpu: ([.spec.containers[].resources.requests.cpu | mcpu] | add)}]
  | group_by(.ns) | map({ns: .[0].ns, cpu: (map(.cpu) | add)})
  | max_by(.cpu) | .ns' > /tmp/top-requests-ns.txt
```

Cross-check with built-in tools:
```bash
kubectl describe node cnpe-worker | grep -A6 "Allocated resources"
kubectl get node cnpe-worker -o jsonpath='{.status.allocatable.cpu}'; echo
```

**Requests vs. usage:** The scheduler only plans by requests. If requests are far above actual
usage (`kubectl top`), the cluster is "full" while the CPUs are idle – exactly this gap shows up
in OpenCost as *idle cost* or low *CPU efficiency*.
