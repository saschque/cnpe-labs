# Lösung 5.8 – Audit Trail

Das Log liegt im Control-Plane-Container von kind:

```bash
kubectl -n demo delete deploy podinfo   # Beispielaktion (oder ein anderes Test-Deployment)

docker exec cnpe-control-plane cat /var/log/kubernetes/audit.log \
  | jq -c 'select(.verb=="delete" and .objectRef.resource=="deployments")
           | {time: .requestReceivedTimestamp, user: .user.username,
              ns: .objectRef.namespace, name: .objectRef.name, code: .responseStatus.code}'

# Änderungen an RoleBindings (letzte Stunde)
SINCE=$(date -u -d '1 hour ago' +%Y-%m-%dT%H:%M:%S)
docker exec cnpe-control-plane cat /var/log/kubernetes/audit.log \
  | jq -c --arg since "$SINCE" 'select(.objectRef.resource=="rolebindings"
           and (.verb|test("create|update|patch|delete"))
           and .requestReceivedTimestamp > $since)
           | {time: .requestReceivedTimestamp, verb, user: .user.username, ns: .objectRef.namespace, name: .objectRef.name}'
```

| Level | Was wird geloggt |
|-------|------------------|
| `None` | Nichts |
| `Metadata` | Wer, wann, welches Verb, welche Ressource – **ohne** Body |
| `Request` | Metadata + Request-Body |
| `RequestResponse` | Metadata + Request- und Response-Body |

**Secrets nur mit `Metadata`:** Bei `Request`/`RequestResponse` stünde der Secret-Inhalt
(base64, also Klartext) im Audit-Log – das Log würde selbst zum Geheimnis.

Weitere Audit-/Compliance-Quellen auf einer Plattform:
- Kyverno `PolicyReport`/`ClusterPolicyReport` und Gatekeeper `status.violations`
- Argo CD: History pro App (`argocd app history`) + Git-Log = wer hat was deployt
- SBOMs (Syft) + Scan-Reports (Trivy) als Pipeline-Artefakte, ggf. als OCI-Attestation
- Kubernetes-Events (`kubectl get events`) sind flüchtig (Standard 1 h) – kein Audit-Ersatz
