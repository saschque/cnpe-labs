# Solution 4.12 – Incident scenarios round 2

| # | Diagnosis | Cause | Fix |
|---|-----------|-------|-----|
| s8-billing | `CreateContainerConfigError`, event: `couldn't find key password in Secret incidents-2/billing-db` | The secret has the key `pass`, not `password` | Change the key reference to `pass` (or add `password` to the secret) |
| s9-search | `RESTARTS` keeps increasing, events: `Liveness probe failed ... connection refused`, then `Killing` | The app needs 20 s, liveness kicks in after ~8 s | Add a `startupProbe` (or `initialDelaySeconds` ≥ 25) |
| s10-uploads | Pod `Pending`, PVC `Pending`, event `storageclass.storage.k8s.io "fast-ssd" not found` | The StorageClass does not exist | Delete the PVC and recreate it with `storageClassName: standard` (the field is immutable!) |
| s11-sync | Logs: `sync failed: HTTP 403 ... cannot list resource "configmaps"` | ServiceAccount `s11-sync` has no permissions | Role (list configmaps) + RoleBinding for the SA |
| s12-resolver | Logs: `DNS lookup failed` | NetworkPolicy `lockdown-egress` blocks all egress, including DNS | A targeted NetworkPolicy that allows egress to kube-dns (53/UDP+TCP) for `app=s12-resolver` |

```bash
# s8
kubectl -n incidents-2 patch deploy s8-billing --type=json -p='[
  {"op":"replace","path":"/spec/template/spec/containers/0/env/1/valueFrom/secretKeyRef/key","value":"pass"}]'

# s9 – the startupProbe gives up to 60 s, after that the liveness probe takes over
kubectl -n incidents-2 patch deploy s9-search --type=strategic -p '
spec:
  template:
    spec:
      containers:
        - name: search
          startupProbe:
            httpGet: {path: /healthz, port: 8080}
            periodSeconds: 3
            failureThreshold: 20'

# s10
kubectl -n incidents-2 get pvc uploads -o yaml > /tmp/pvc.yaml
kubectl -n incidents-2 delete pvc uploads
sed -i 's/fast-ssd/standard/' /tmp/pvc.yaml
# remove resourceVersion/uid/status from /tmp/pvc.yaml (or quickly rewrite it), then:
kubectl apply -f /tmp/pvc.yaml

# s11
kubectl -n incidents-2 create role configmap-reader --verb=get,list,watch --resource=configmaps
kubectl -n incidents-2 create rolebinding s11-sync --role=configmap-reader --serviceaccount=incidents-2:s11-sync
kubectl -n incidents-2 rollout restart deploy s11-sync     # or wait for the next restart

# s12
kubectl apply -f - <<'EOF'
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata: {name: s12-allow-dns, namespace: incidents-2}
spec:
  podSelector: {matchLabels: {app: s12-resolver}}
  policyTypes: [Egress]
  egress:
    - to:
        - namespaceSelector: {matchLabels: {kubernetes.io/metadata.name: kube-system}}
          podSelector: {matchLabels: {k8s-app: kube-dns}}
      ports:
        - {protocol: UDP, port: 53}
        - {protocol: TCP, port: 53}
EOF
```

**Liveness vs. readiness vs. startup:**
- **Startup** – "has the app finished starting?" While it fails, the other probes don't run.
- **Liveness** – "is the app hung?" Failure → the container is **restarted**.
- **Readiness** – "can the app take traffic?" Failure → the pod is removed from the **endpoints**, no restart.
