# Lösung 4.2 – PromQL

```promql
# 1. CPU-Cores pro Namespace
sum by (namespace) (rate(container_cpu_usage_seconds_total{container!=""}[5m]))

# 2. Memory Working Set pro Pod in demo
sum by (pod) (container_memory_working_set_bytes{namespace="demo", container!=""})

# 3. Top 5 Container nach Restarts (1h)
topk(5, increase(kube_pod_container_status_restarts_total[1h]))

# 4. Request-Rate pro Statuscode
sum by (status) (rate(http_requests_total{namespace="demo"}[5m]))

# 5. p95-Latenz
histogram_quantile(0.95, sum by (le) (rate(http_request_duration_seconds_bucket{namespace="demo"}[5m])))

# 6. Anteil nicht-Running-Pods pro Namespace
sum by (namespace) (kube_pod_status_phase{phase!="Running"})
  / sum by (namespace) (kube_pod_status_phase)
```

## Merkhilfen
- `rate()` nur auf **Counter** (`_total`, `_seconds_total`, `_bucket`), immer mit Range `[5m]`.
- `increase()` = `rate() × Zeitraum` – gut für „wie viele in der letzten Stunde“.
- `histogram_quantile()` braucht `le` im `by()`.
- `container!=""` filtert die Pod-Summenzeile (cAdvisor) heraus, sonst doppelte Werte.
- `kube_*`-Metriken kommen von kube-state-metrics (Zustand), `container_*` von cAdvisor (Verbrauch).
- Schnell testen per API:
  `curl -sG localhost:9090/api/v1/query --data-urlencode 'query=up' | jq '.data.result'`
