# Solution 4.2 – PromQL

```promql
# 1. CPU cores per namespace
sum by (namespace) (rate(container_cpu_usage_seconds_total{container!=""}[5m]))

# 2. Memory working set per pod in demo
sum by (pod) (container_memory_working_set_bytes{namespace="demo", container!=""})

# 3. Top 5 containers by restarts (1h)
topk(5, increase(kube_pod_container_status_restarts_total[1h]))

# 4. Request rate per status code
sum by (status) (rate(http_requests_total{namespace="demo"}[5m]))

# 5. p95 latency
histogram_quantile(0.95, sum by (le) (rate(http_request_duration_seconds_bucket{namespace="demo"}[5m])))

# 6. Share of non-running pods per namespace
sum by (namespace) (kube_pod_status_phase{phase!="Running"})
  / sum by (namespace) (kube_pod_status_phase)
```

## Things to remember
- Use `rate()` only on **counters** (`_total`, `_seconds_total`, `_bucket`), always with a range `[5m]`.
- `increase()` = `rate() × time range` – good for "how many in the last hour".
- `histogram_quantile()` needs `le` in the `by()`.
- `container!=""` filters out the pod-level sum series (cAdvisor), otherwise you double count.
- `kube_*` metrics come from kube-state-metrics (state), `container_*` from cAdvisor (usage).
- Quick test via the API:
  `curl -sG localhost:9090/api/v1/query --data-urlencode 'query=up' | jq '.data.result'`
