# Solution 4.9 – Analyzing logs

```bash
# 1. ERROR lines of all pods (label selector), last 10 minutes, container app only
kubectl -n logs-demo logs -l app=chatty -c app --since=10m --tail=-1 \
  | grep -c ERROR > /tmp/error-count.txt
cat /tmp/error-count.txt

# 2. Pod with the most errors
for p in $(kubectl -n logs-demo get pods -l app=chatty -o name); do
  echo "$(kubectl -n logs-demo logs "$p" -c app --since=10m | grep -c ERROR) ${p#pod/}"
done | sort -rn | head -1 | awk '{print $2}' > /tmp/noisy-pod.txt

# Shorter with --prefix:
kubectl -n logs-demo logs -l app=chatty -c app --since=10m --tail=-1 --prefix \
  | grep ERROR | awk '{print $1}' | sort | uniq -c | sort -rn | head -1

# 3. Only the sidecar, or all containers with a prefix
kubectl -n logs-demo logs deploy/chatty -c sidecar
kubectl -n logs-demo logs -l app=chatty --all-containers --prefix --tail=20
```

**Pitfalls:**
- With `-l` (label selector), `kubectl logs` shows only the last **10 lines** per pod by default
  → `--tail=-1` for everything.
- Multiple containers → without `-c` you get an error (or the default container).
- `--previous` shows the logs of the **previous** (crashed) container.
- Logs are gone as soon as the pod is deleted → central log collection (e.g. OTel Collector
  with the `filelog` receiver as a DaemonSet, Loki, Elasticsearch).
