# Lösung 4.7 – Incident-Szenarien

Vorgehen bei jedem Incident: **Events → describe → logs → fixen → verifizieren.**
```bash
kubectl -n incidents get pods,deploy,rs
kubectl -n incidents get events --sort-by=.lastTimestamp | tail -20
```

| # | Symptom | Diagnose | Ursache | Fix |
|---|---------|----------|---------|-----|
| s1-web | `ImagePullBackOff` | `describe pod` → `manifest for nginx:1.277 not found` | Tippfehler im Tag | `kubectl -n incidents set image deploy/s1-web web=nginx:1.27` |
| s2-api | `CrashLoopBackOff` | `logs --previous` → `FATAL: DATABASE_URL not set` | Fehlende Env-Variable | `kubectl -n incidents set env deploy/s2-api DATABASE_URL=postgres://db:5432/app` |
| s3-worker | `OOMKilled` (Exit 137) | `describe pod` → `Last State: Terminated, Reason: OOMKilled` | Braucht 150M, Limit 100Mi | Limit erhöhen: `kubectl -n incidents set resources deploy/s3-worker --limits=memory=256Mi` |
| s4-batch | `Pending` | Events → `0/3 nodes are available: node(s) didn't match Pod's node affinity/selector` | `nodeSelector disktype=ssd`, kein Node hat das Label | nodeSelector entfernen (`kubectl -n incidents patch deploy s4-batch --type=json -p='[{"op":"remove","path":"/spec/template/spec/nodeSelector"}]'`) **oder** Node labeln |
| s5-frontend | Service liefert nichts | `kubectl -n incidents get endpoints s5-frontend` → `<none>` | Selector `app: frontend` passt nicht; zudem `targetPort 8080` statt 80 | `kubectl -n incidents patch svc s5-frontend -p '{"spec":{"selector":{"app":"s5-frontend"},"ports":[{"port":80,"targetPort":80}]}}'` |
| s6-cache | `0/1 Ready` | `describe pod` → `Readiness probe failed: dial tcp ...:6380: connect: connection refused` | Probe auf falschem Port | Port in der Probe auf 6379 ändern (`kubectl edit` oder JSON-Patch) |
| s7-report | Rollout hängt / `ProgressDeadlineExceeded` | `rollout status` hängt; neue Pods `Pending` oder Events `exceeded quota` | 3 × 1500Mi > Quota 2Gi (`requests.memory`) | Request senken, z. B. `--requests=memory=64Mi`, oder Quota erhöhen |

```bash
# s6 per JSON-Patch
kubectl -n incidents patch deploy s6-cache --type=json \
  -p='[{"op":"replace","path":"/spec/template/spec/containers/0/readinessProbe/tcpSocket/port","value":6379}]'

# s7
kubectl -n incidents set resources deploy/s7-report --requests=memory=64Mi
kubectl -n incidents rollout status deploy/s7-report
```

## Exit-Codes & Status, die man kennen sollte

| Status / Code | Bedeutung |
|---------------|-----------|
| `ErrImagePull` / `ImagePullBackOff` | Image/Tag falsch, Registry nicht erreichbar, fehlendes `imagePullSecret` |
| `CrashLoopBackOff` | Container beendet sich wiederholt – `logs --previous`! |
| Exit `137` | SIGKILL – meist `OOMKilled` |
| Exit `143` | SIGTERM – regulär beendet oder Liveness-Probe fehlgeschlagen |
| Exit `1` / `2` | Anwendungsfehler / Fehlbedienung |
| `CreateContainerConfigError` | Referenzierte ConfigMap/Secret (oder Key) fehlt |
| `Pending` | Scheduling: Ressourcen, nodeSelector/Affinity, Taints, PVC nicht gebunden |
| `exceeded quota` (Event am ReplicaSet!) | ResourceQuota verhindert Pod-Erstellung – `kubectl describe rs` |
