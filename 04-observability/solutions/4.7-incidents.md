# Solution 4.7 – Incident scenarios

Approach for every incident: **events → describe → logs → fix → verify.**
```bash
kubectl -n incidents get pods,deploy,rs
kubectl -n incidents get events --sort-by=.lastTimestamp | tail -20
```

| # | Symptom | Diagnosis | Cause | Fix |
|---|---------|-----------|-------|-----|
| s1-web | `ImagePullBackOff` | `describe pod` → `manifest for nginx:1.277 not found` | Typo in the tag | `kubectl -n incidents set image deploy/s1-web web=nginx:1.27` |
| s2-api | `CrashLoopBackOff` | `logs --previous` → `FATAL: DATABASE_URL not set` | Missing env variable | `kubectl -n incidents set env deploy/s2-api DATABASE_URL=postgres://db:5432/app` |
| s3-worker | `OOMKilled` (exit 137) | `describe pod` → `Last State: Terminated, Reason: OOMKilled` | Needs 150M, limit is 100Mi | Raise the limit: `kubectl -n incidents set resources deploy/s3-worker --limits=memory=256Mi` |
| s4-batch | `Pending` | Events → `0/3 nodes are available: node(s) didn't match Pod's node affinity/selector` | `nodeSelector disktype=ssd`, no node has the label | Remove the nodeSelector (`kubectl -n incidents patch deploy s4-batch --type=json -p='[{"op":"remove","path":"/spec/template/spec/nodeSelector"}]'`) **or** label a node |
| s5-frontend | Service returns nothing | `kubectl -n incidents get endpoints s5-frontend` → `<none>` | Selector `app: frontend` does not match; also `targetPort 8080` instead of 80 | `kubectl -n incidents patch svc s5-frontend -p '{"spec":{"selector":{"app":"s5-frontend"},"ports":[{"port":80,"targetPort":80}]}}'` |
| s6-cache | `0/1 Ready` | `describe pod` → `Readiness probe failed: dial tcp ...:6380: connect: connection refused` | Probe on the wrong port | Change the probe port to 6379 (`kubectl edit` or JSON patch) |
| s7-report | Rollout stuck / `ProgressDeadlineExceeded` | `rollout status` hangs; new pods `Pending` or events `exceeded quota` | 3 × 1500Mi > quota 2Gi (`requests.memory`) | Lower the request, e.g. `--requests=memory=64Mi`, or raise the quota |

```bash
# s6 via JSON patch
kubectl -n incidents patch deploy s6-cache --type=json \
  -p='[{"op":"replace","path":"/spec/template/spec/containers/0/readinessProbe/tcpSocket/port","value":6379}]'

# s7
kubectl -n incidents set resources deploy/s7-report --requests=memory=64Mi
kubectl -n incidents rollout status deploy/s7-report
```

## Exit codes & states you should know

| State / code | Meaning |
|--------------|---------|
| `ErrImagePull` / `ImagePullBackOff` | Wrong image/tag, registry unreachable, missing `imagePullSecret` |
| `CrashLoopBackOff` | The container exits repeatedly – `logs --previous`! |
| Exit `137` | SIGKILL – usually `OOMKilled` |
| Exit `143` | SIGTERM – stopped normally or the liveness probe failed |
| Exit `1` / `2` | Application error / misuse |
| `CreateContainerConfigError` | A referenced ConfigMap/Secret (or key) is missing |
| `Pending` | Scheduling: resources, nodeSelector/affinity, taints, PVC not bound |
| `exceeded quota` (event on the ReplicaSet!) | A ResourceQuota prevents pod creation – `kubectl describe rs` |
