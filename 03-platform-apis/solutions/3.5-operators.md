# Solution 3.5 – Working with operators

```bash
# 1. Argo CD CRDs
kubectl api-resources --api-group=argoproj.io
kubectl get crd | grep argoproj

# 2. Controller + ServiceAccount
kubectl -n argocd get statefulset,deploy
kubectl -n argocd get statefulset argocd-application-controller \
  -o jsonpath='{.spec.template.spec.serviceAccountName}'; echo

# 3. Permissions of the ServiceAccount
kubectl auth can-i --list --as=system:serviceaccount:argocd:argocd-application-controller
kubectl get clusterrolebinding -o wide | grep argocd-application-controller

# 4. A CRD's fields without docs
kubectl explain application.spec.syncPolicy --recursive
kubectl explain webapp.spec
kubectl explain canary.spec.analysis --api-version=flagger.app/v1beta1

# 5. Log level debug
kubectl -n argocd patch configmap argocd-cmd-params-cm --type=merge \
  -p '{"data":{"controller.log.level":"debug"}}'
kubectl -n argocd rollout restart statefulset argocd-application-controller
kubectl -n argocd logs statefulset/argocd-application-controller | head
```

## The operator pattern in one sentence
An operator = CRD (declarative API) + controller (reconcile loop: *watch → diff → act*) that
automates operational knowledge. Things that help in the exam:
- `status.conditions` and `status.observedGeneration` show whether the controller has seen the
  current spec.
- Finalizers (`metadata.finalizers`) block deletion until the controller has cleaned up.
  If an object hangs in `Terminating`, the controller is usually gone – only remove finalizers
  manually in an emergency.
- `ownerReferences` show which object created another one.
