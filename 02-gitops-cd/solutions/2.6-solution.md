# Lösung 2.6 – Broken App

```bash
kubectl -n argocd get application broken-app -o jsonpath='{.status.conditions}' | jq
argocd app get broken-app
```

| # | Fehler | Symptom | Fix |
|---|--------|---------|-----|
| 1 | `project: platform` existiert nicht | Condition `InvalidSpecError: application references project platform which does not exist` | `project: default` (oder AppProject anlegen) |
| 2 | Tippfehler im Pfad `kustomize-guestbok` | `ComparisonError: app path does not exist` | `path: kustomize-guestbook` |
| 3 | Namespace `broken` existiert nicht | Sync schlägt fehl: `namespaces "broken" not found` | `syncOptions: [CreateNamespace=true]` oder Namespace anlegen |

```bash
kubectl -n argocd patch application broken-app --type=merge -p '
spec:
  project: default
  source:
    path: kustomize-guestbook
  syncPolicy:
    syncOptions: ["CreateNamespace=true"]
'
argocd app sync broken-app     # oder warten
```

## Allgemeine Troubleshooting-Checkliste Argo CD

1. `status.conditions` lesen – fast jede Ursache steht dort.
2. `argocd app diff <app>` – was weicht ab?
3. Repo erreichbar? `argocd repo list`, Logs von `argocd-repo-server`.
4. Rendering-Fehler (Helm/Kustomize)? Lokal `kustomize build` / `helm template` testen.
5. AppProject erlaubt Quelle/Ziel? `kubectl -n argocd get appproject <p> -o yaml`
   (`sourceRepos`, `destinations`, `clusterResourceWhitelist`).
6. Health `Progressing` hängt? → Ressource selbst debuggen (`kubectl describe`, Events).
7. Hard Refresh: `argocd app get <app> --hard-refresh`.
