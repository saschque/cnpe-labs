# Solution 2.6 – Broken app

```bash
kubectl -n argocd get application broken-app -o jsonpath='{.status.conditions}' | jq
argocd app get broken-app
```

| # | Error | Symptom | Fix |
|---|-------|---------|-----|
| 1 | `project: platform` does not exist | Condition `InvalidSpecError: application references project platform which does not exist` | `project: default` (or create the AppProject) |
| 2 | Typo in the path `kustomize-guestbok` | `ComparisonError: app path does not exist` | `path: kustomize-guestbook` |
| 3 | Namespace `broken` does not exist | Sync fails: `namespaces "broken" not found` | `syncOptions: [CreateNamespace=true]` or create the namespace |

```bash
kubectl -n argocd patch application broken-app --type=merge -p '
spec:
  project: default
  source:
    path: kustomize-guestbook
  syncPolicy:
    syncOptions: ["CreateNamespace=true"]
'
argocd app sync broken-app     # or wait
```

## General Argo CD troubleshooting checklist

1. Read `status.conditions` – almost every cause is listed there.
2. `argocd app diff <app>` – what differs?
3. Is the repo reachable? `argocd repo list`, logs of `argocd-repo-server`.
4. Rendering errors (Helm/Kustomize)? Test locally with `kustomize build` / `helm template`.
5. Does the AppProject allow the source/destination? `kubectl -n argocd get appproject <p> -o yaml`
   (`sourceRepos`, `destinations`, `clusterResourceWhitelist`).
6. Health stuck in `Progressing`? → debug the resource itself (`kubectl describe`, events).
7. Hard refresh: `argocd app get <app> --hard-refresh`.
