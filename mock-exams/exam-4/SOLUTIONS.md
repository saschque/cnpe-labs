### 1 – Cost per team
```bash
kubectl -n opencost port-forward svc/opencost 9003:9003 &
curl -sG http://localhost:9003/allocation/compute \
  -d window=24h -d aggregate=label:team -d accumulate=true > /tmp/m4-cost.json
jq -r '.data[0] | to_entries | map(select(.key | startswith("__") | not))
       | max_by(.value.totalCost) | .key' /tmp/m4-cost.json > /tmp/m4-top-team.txt
```
Depending on the OpenCost version, the keys look like `blue` or `team=blue` – both are accepted.

### 3 – Anti-affinity
```bash
kubectl -n m4-blue patch deploy api --type=strategic -p '
spec:
  template:
    spec:
      affinity:
        podAntiAffinity:
          requiredDuringSchedulingIgnoredDuringExecution:
            - labelSelector: {matchLabels: {app: api}}
              topologyKey: kubernetes.io/hostname'
```
With 2 worker nodes, 2 replicas fit. A third replica would stay `Pending` (that is what "hard" means).
Note: During a rolling update with `maxSurge`, the new pod may have no free node – then
`maxSurge: 0, maxUnavailable: 1` helps.

### 6 – Fix Tekton
1. `taskRef: m4-lint` – the task is called `m4-linter`.
2. The pipeline passes `dir`, the task expects `path`.
3. The PipelineRun does not bind the workspace `shared`.
```bash
kubectl -n ci patch pipeline m4-ci --type=json -p='[
  {"op":"replace","path":"/spec/tasks/0/taskRef/name","value":"m4-linter"},
  {"op":"replace","path":"/spec/tasks/0/params/0/name","value":"path"}]'
kubectl create -f - <<'EOF'
apiVersion: tekton.dev/v1
kind: PipelineRun
metadata: {generateName: m4-ci-run-, namespace: ci}
spec:
  pipelineRef: {name: m4-ci}
  workspaces:
    - name: shared
      emptyDir: {}
EOF
tkn pipelinerun logs --last -f -n ci
```

### 8 – CRD from a specification
```yaml
apiVersion: apiextensions.k8s.io/v1
kind: CustomResourceDefinition
metadata: {name: backups.ops.m4.io}
spec:
  group: ops.m4.io
  scope: Namespaced
  names: {kind: Backup, plural: backups, singular: backup, shortNames: [bk], categories: [ops]}
  versions:
    - name: v1
      served: true
      storage: true
      additionalPrinterColumns:
        - {name: Schedule, type: string, jsonPath: .spec.schedule}
        - {name: Retention, type: integer, jsonPath: .spec.retentionDays}
        - {name: Target, type: string, jsonPath: .spec.target.name}
      schema:
        openAPIV3Schema:
          type: object
          properties:
            spec:
              type: object
              required: [schedule, target]
              properties:
                schedule: {type: string}
                retentionDays: {type: integer, minimum: 1, maximum: 90, default: 7}
                target:
                  type: object
                  required: [kind, name]
                  properties:
                    kind: {type: string, enum: [Database, Volume]}
                    name: {type: string}
---
apiVersion: ops.m4.io/v1
kind: Backup
metadata: {name: nightly, namespace: m4-blue}
spec:
  schedule: "0 2 * * *"
  target: {kind: Database, name: orders}
```

### 9 – Crossplane troubleshooting
1. `compositeTypeRef.apiVersion: messaging.m4.io/v1beta1` – the XRD only serves `v1alpha1`.
   The XR cannot use the Composition.
2. `retentionDays` is an integer, ConfigMap `data` only accepts strings → `convert` transform is missing.
```bash
kubectl -n m4-blue describe queue jobs          # conditions/events
kubectl patch composition queue-configmap --type=json -p='[
  {"op":"replace","path":"/spec/compositeTypeRef/apiVersion","value":"messaging.m4.io/v1alpha1"},
  {"op":"add","path":"/spec/pipeline/0/input/resources/0/patches/1/transforms",
   "value":[{"type":"convert","convert":{"toType":"string"}}]}]'
kubectl -n m4-blue get cm jobs -o jsonpath='{.data.retention}'
```
`compositeTypeRef` is immutable on some versions → then delete and recreate the Composition.

### 10 – Mutation
```yaml
apiVersion: kyverno.io/v1
kind: ClusterPolicy
metadata: {name: m4-label-backups}
spec:
  rules:
    - name: add-label
      match:
        any:
          - resources: {kinds: ["ops.m4.io/v1/Backup"]}
      mutate:
        patchStrategicMerge:
          metadata:
            labels:
              platform.m4.io/managed: "true"
```
Existing objects are only mutated on their next update (or via `mutateExistingOnPolicyUpdate`).

### 11 – Stuck object
The widget has the finalizer `legacy.m4.io/cleanup`, but there is no controller that removes it.
```bash
kubectl -n m4-blue get widget stuck -o jsonpath='{.metadata.finalizers}'
kubectl -n m4-blue patch widget stuck --type=merge -p '{"metadata":{"finalizers":null}}'
```
Only remove finalizers manually when you know that the cleanup is no longer needed (or has been
done by hand) – otherwise external resources may be left behind.

### 14 – Broken rollout
1. Image tag `nginx:1.27-hardened` does not exist → new ReplicaSet in `ImagePullBackOff`,
   rollout stuck (`maxUnavailable: 0` keeps the old pods alive).
2. HPA `scaleTargetRef` points to `web-app` instead of `web` → `FailedGetScale`.
```bash
kubectl -n m4-incident rollout history deploy web
kubectl -n m4-incident rollout undo deploy web
kubectl -n m4-incident patch deploy web -p '{"spec":{"revisionHistoryLimit":5}}'
kubectl -n m4-incident patch hpa web --type=merge -p '{"spec":{"scaleTargetRef":{"name":"web"}}}'
printf 'web: image tag nginx:1.27-hardened does not exist (ImagePullBackOff)\nhpa: scaleTargetRef points to web-app instead of web\n' > /tmp/m4-incident.txt
```

### 15 – Least privilege
```bash
kubectl -n m4-ci create sa deployer
kubectl -n m4-incident create role web-deployer --verb=get,patch --resource=deployments.apps --resource-name=web
kubectl -n m4-incident create rolebinding web-deployer --role=web-deployer --serviceaccount=m4-ci:deployer
kubectl auth can-i patch deploy/web -n m4-incident --as=system:serviceaccount:m4-ci:deployer      # yes
kubectl auth can-i patch deploy/worker -n m4-incident --as=system:serviceaccount:m4-ci:deployer   # no
```
`resourceNames` does not work with `list`/`watch`/`create` – those verbs have no object name.

### 17 – Audit trail
```bash
docker exec cnpe-control-plane cat /var/log/kubernetes/audit.log | jq -r '
  select(.verb=="delete" and .objectRef.resource=="configmaps" and .objectRef.name=="m4-evidence")
  | "\(.requestReceivedTimestamp) \(.user.username) impersonated=\(.impersonatedUser.username // "-")"'
echo mallory > /tmp/m4-audit.txt
```
With `--as`, the audit log records the real caller in `user` and the identity used in
`impersonatedUser` – the change was made as `mallory`.
